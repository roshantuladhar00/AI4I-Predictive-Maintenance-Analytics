## Deployment model

The original training code uses a stratified 80/20 split with seed 42 and a preprocessing pipeline for product type and sensor measurements. `Temp_diff` and `Torque_RPM_ratio` are engineered features. Identifiers and outcome-specific failure flags are excluded by the preprocessor.

The deployed soft-voting classifier combines:

- Random forest: 400 trees, balanced class weights, minimum leaf size 2; isotonic calibration with 3-fold CV.
- Gradient boosting.
- MLP: hidden layers 64 and 32, maximum 500 iterations.

Voting weights are **2:2:1**. Only the random forest member is explicitly calibrated. The overall ensemble output is a model score displayed as a percentage; whole-ensemble probability calibration has not been established.

## Why this threshold is used

The original training rule is retained:

1. Train the ensemble on the training split.
2. Score the held-out split.
3. Evaluate precision and recall at the candidate score thresholds.
4. Keep candidates with failure recall at least 95%.
5. Select the candidate with the greatest precision and save its full value in `models/threshold.json`.

The rule includes lower-recall fallback targets, but the bundled run meets the first 95% target. It does **not** impose the 5% false-positive cap from the earlier, separate workflow.

The regenerated threshold is **0.025743180189271207**. On the 2,000 observations used for threshold selection:

| Decision threshold | Failures detected | Failures missed | False alarms | Failure recall | Failure precision | False-positive rate |
|---|---:|---:|---:|---:|---:|---:|
| 0.5 | 52 / 68 | 16 | 6 / 1,932 | 76.47% | 89.66% | 0.31% |
| 0.025743180189271207 | 65 / 68 | 3 | 163 / 1,932 | 95.59% | 28.51% | 8.44% |

ROC-AUC is 0.9743 and average precision (reported as PR-AUC in the source) is 0.8807. These are local regenerated results, not copied original scores. The held-out observations were also used to choose the threshold, so the tuned results are threshold-selection results, not an untouched final-test estimate.

The original gauge has color bands at **35%** and **70%**. Those visual risk tiers differ from the tuned decision threshold. The model's saved threshold is the gauge marker. The simulation separately uses 70% for high-risk alerts and 90% for triggering maintenance. These original rules were preserved; a low color-band label can coexist with a score above the much lower tuned classification threshold.

For a presentation: “The gauge shows the model's failure score. Its marker shows the classification threshold selected to detect at least 95% of failures on the threshold-selection split. Lowering this threshold detects more failures and raises more false alarms.” Do not describe the number as a validated probability of failure within a specified future time window.

## RUL and survival interpretation

The RUL target is constructed from assumed type-specific wear limits and a sensor-stress formula, capped at 500 minutes. It is not observed remaining useful life. In the deployment training run, random forest regression was selected with MAE about 3.08 minutes against this synthetic target; that error does not measure accuracy against real machine lifetimes.

For fidelity, notebook 09 retains its exploratory settings: stress weights 0.40 torque, 0.25 wear, 0.20 temperature difference, and 0.15 inverse RPM. Deployment `src/train.py` uses 0.35 torque, 0.25 wear, 0.20 temperature difference, and 0.20 inverse RPM. Its gradient-boosting regressor also uses 200 rather than 300 estimators. The notebook's scenario helper uses approximate normalizers, whereas deployment inference reads dataset maxima. Dashboard artifacts are always generated by `python -m src.train`; running notebook 09 does not overwrite them.

The survival demonstration treats tool wear as duration and the observed failure flag as event status. AI4I does not establish longitudinal machine lifetimes or valid censoring times. Kaplan–Meier, Cox, DeepSurv, and CoxCC outputs illustrate methods under that proxy interpretation.

Notebook 07 uses its held-out split for neural-network early stopping and voting-weight selection. Its comparison therefore follows the original exploratory design, not a new unbiased final-test protocol. Its LSTM treats each row as one timestep, so it does not demonstrate learning from a genuine sequence of machine history.
